# コーディング規約

技術スタックは `.claude/rules/tech-stack.md`、仕様は `docs/user-story-map.md` を参照する。ここに書いたディレクトリ名・ツールは tech-stack.md の暫定案を前提にしており、暫定案が変われば合わせて更新する。

## 全般

- コード内のコメント、テスト名、コミットメッセージの本文は日本語で書く。識別子（変数名・関数名・ファイル名）は英語。
- コメントは「なぜそうするか」を書く。コードを読めばわかる「何をするか」は書かない。
- 仕様に対応するコードやテストには、必要に応じてストーリー ID（例：`US-E1`）を書く。
- 未確定事項（USM の Q-xx／T-xx）に依存する箇所は、独断で実装せず確認する。暫定実装する場合は `// TODO(T-05): …` のように ID を残す。
- 使われていないコード、デバッグ用の `console.log`、コメントアウトしたコードを残さない。

## TypeScript

- `strict` を有効にする。`any` は使わない。やむを得ない場合は `unknown` から型を絞り込む。
- 型アサーション（`as`）と非 null アサーション（`!`）は避ける。
- 衝動の種類は文字列リテラルのユニオン型で定義し、順序は1つの定数配列から導く。順序や種類をコード中に重複して書かない。

```ts
// 例：衝動の定義は1か所に集約する
export const IMPULSE_KEYS = ['ikki', 'revolution', 'exodus', 'festival'] as const
export type ImpulseKey = (typeof IMPULSE_KEYS)[number]
```

- 上限（10票）、ウィンドウ（12時間）などの仕様値は名前付き定数にする。マジックナンバーを書かない。
- 時刻はミリ秒の数値（`number`、エポックミリ秒）で扱う。

## Vue コンポーネント

- `<script setup lang="ts">` と Composition API で書く。Options API は使わない。
- コンポーネントのファイル名は PascalCase（例：`ImpulseSlide.vue`）。
- props と emits は型で定義する（`defineProps<…>()`、`defineEmits<…>()`）。
- コンポーネントは表示とユーザー操作の受け渡しに専念させ、投票・上限・集計のロジックを書かない。ロジックは composable とドメイン層に置く。
- 4つの衝動で構造が同じ部分は1つのコンポーネントにまとめ、データで差し替える。エンブレムの SVG は衝動ごとに別コンポーネントにしてよい。

## ディレクトリと責務

Nuxt 4 の構成（`app/`）に従う。

| 場所 | 責務 |
|---|---|
| `app/app.vue` または `app/pages/index.vue` | メイン画面1枚。ページ遷移を作らない |
| `app/components/` | 表示コンポーネント |
| `app/composables/` | 画面の状態と操作（現在の衝動、投票、残り枠など）。`use` で始める |
| `app/domain/` | フレームワークに依存しない純粋なロジック（ローリングウィンドウ、上限判定、集計）。Vue・Nuxt を import しない |
| `app/data/` | 集計数の取得・投票の記録を担うデータ層（下記） |
| `app/assets/` | CSS、フォント指定 |
| `tests/` | 単体テストと E2E テスト |

- `server/` ディレクトリは作らない（バックエンドなし）。

## ロジックの書き方

- 12時間の判定や上限判定は、現在時刻を引数で受け取る純粋関数にする。関数の中で `Date.now()` を直接呼ばない。
- 時刻の取得は「時計」として1か所から注入し、テストで差し替えられるようにする。
- 投票の記録は「投票時刻の配列」として衝動ごとに持ち、12時間を超えたものを除外して数える（最後の投票時刻からの経過ではなく、各票ごとのローリングウィンドウ）。
- 集計数は「他ユーザー分（模擬値） ＋ 自分の有効票数」として算出し、表示用の値を別途加算して持たない。
- 他ユーザー分の模擬変動（US-D3）はデータ層のモック実装に閉じ込める。乱数は時計と同様に注入し、テストで差し替えられるようにする。
- 投票は楽観的更新にする。確定待ちの間の票も「自分の票」として数え、確定後に値が巻き戻らないようにする。
- 票には一意な ID を付け、同じ ID の票を二重に記録しない（冪等性）。
- 検証用の設定（US-V1・V2）は `runtimeConfig.public` で定義し、環境変数 `NUXT_PUBLIC_VOTE_WINDOW`／`NUXT_PUBLIC_SHOW_PIPS` から受け取る。読み取りと値の検証は1か所にまとめ、不正な値は既定値（`12h`／`true`）に倒す。ドメイン層には設定値を引数で渡し、ドメイン層から設定を直接読まない。

## モックとバックエンドの境界

- 集計数の取得、投票の送信、上限判定の入口は、データ層のインターフェース経由にする。コンポーネントや composable からモックデータを直接参照しない。
- 実装はモック（`mockCountSource.ts`）と AWS（`apiCountSource.ts`）の2つ。どちらを使うかは `createCountSource.ts` だけで決め、画面やcomposable は実装の違いを知らない。
- モックの初期値は1つのファイルにまとめ、モックであることがファイル名・コメントで明確にわかるようにする。
- 実際の集計だと誤認させる文言（「リアルタイム集計」「全国の〇人」など）を、UI 文言にもコード上の表示用文字列にも書かない。

## スタイル

- コンポーネントのスタイルは `<style scoped>` で書く。共通の値は CSS カスタムプロパティにする。
- 衝動ごとのテーマ色はデータとして定義し、CSS カスタムプロパティで適用する。色を CSS に直接散らばらせない。
- モバイルファーストで書き、PC 向けはメディアクエリまたはコンテナクエリで上書きする。
- 文字サイズ・余白は `clamp()` などで表示領域に応じて伸縮させる（モックに合わせる）。
- アニメーションは CSS で実装し、`transform` と `opacity` を中心に使う。
- `prefers-reduced-motion: reduce` で常時の装飾アニメーションを止める。投票時の演出（揺れ・拡大・+1・フラッシュ）は止めない（モックどおり）。

## アクセシビリティ

- 操作要素は `<button>` などのネイティブ要素で作る。`div` にクリックを付けない。
- 操作要素にはアクセシブルな名前（表示テキストまたは `aria-label`）を付ける。
- フォーカスリングを消さない（`:focus-visible` で表示する）。
- 表示していない衝動のスライドは `aria-hidden="true"` にし、中の要素を Tab で辿れないようにする。
- 残り枠や上限の変化は `aria-live="polite"` で通知する。
- 文字色と背景色のコントラスト比は 4.5:1 以上にする。

## テスト

- ドメイン層（`app/domain/`）はすべて単体テストを書く。特に次の境界を必ず検証する。
  - 10票目は受け付け、11票目は拒否する
  - 衝動ごとに上限が独立している
  - 投票からちょうど12時間で集計対象外になり、枠が回復する
- 受け入れ条件はストーリー ID ごとにテストを用意し、テスト名にストーリー ID を含める（例：`US-E1: 11票目は集計数を増やさない`）。
- 時間に依存するテストは注入した時計で時刻を進める。実時間を待たない。
- E2E はスマホ（390×844）と PC（1280×800）の両方で、切替・投票・上限の主要な流れを確認する。

## 作業の進め方

- 変更後は lint・型チェック・テストを実行し、通ってから完了とする。失敗が残る場合はその旨を報告する。
- 既存のファイル構成・規約を確認してから変更する。構成を作り直さない。
- 1つの変更は1つの目的に絞る。仕様にない機能を「ついでに」追加しない。
