# ユーザーストーリーマップ（USM）

> 「世界の空気を、衝動で測る。」

- 作成日：2026-10-17
- 状態：第2版（指示とモックの差異をモック優先で解消）。フェーズ1（モック）を実装済み（2026-10-24）
- 入力：ミッション指示（確定仕様）、UI モック `衝動で測るアプリ モック.html`
- 凡例：**【確定】** = 指示で確定済み／**【モック】** = モックから読み取り、確定した事項／**【要確認】** = 未確定。勝手に確定させない（§9 の質問 ID を参照）
- 判断基準：**指示とモックが食い違う場合はモックを正とする**（2026-10-23 決定）
- 進め方：**フェーズ1 = モックの状態でリリース**（フロントエンドのみ）→ **フェーズ2 = AWS でバックエンドを構築**（2026-10-24 決定）

---

## 1. プロダクトの目的と対象範囲

### 1.1 目的

政治・経済・天候・国際情勢など、社会や世界の状況に対して人々が抱く「衝動」を集め、その数を通して世の中の空気を測る。

- 個人の悩みや欲求を尋ねるものではない。社会や世界に対してどんな衝動が生まれているかを可視化する。
- アンケート、SNS、ニュースアプリ、共感サービス、コミュニティ、行動を呼びかけるプラットフォームでは**ない**。

### 1.2 ユーザーの目的（ゴール）

| ID | ユーザーの目的 |
|---|---|
| G1 | いま世の中にどんな衝動がどれだけ渦巻いているか、ひと目で知りたい |
| G2 | 自分が世の中に対して抱いた衝動を、1票として数に加えたい |

### 1.3 対象範囲（今回）

- Nuxt ベースのフロントエンドのみ。バックエンド・データベースなし。
- 実際の複数ユーザー間の集計は行わず、モックデータで表現する。
- 画面はメイン画面1つ。モバイル主軸、PC にも対応するレスポンシブ UI。

## 2. UI モックの確認結果

### 2.1 モックの所在と構成

- ファイル：リポジトリ直下の `衝動で測るアプリ モック.html`（**git 未追跡**）
- 形式：バンドル済み HTML。内部に2つの画面を含む。
  - 「メイン（PC）」1280×800
  - 「メイン（スマホ）」390×844
- スマホ版は PC 版と**同一のコンポーネント**を 390×844 に固定表示したもの。レイアウトは同じ実装をコンテナ幅で出し分けている（幅 700px 以下で矢印ボタンを非表示）。
- 確認方法：バンドルを展開し、テンプレート（HTML/CSS）とロジック（JavaScript）をソースレベルで読んだ。ブラウザでのスクリーンショット確認は行っていない。

### 2.2 画面構成（上から順）

| 領域 | 要素 | 内容 |
|---|---|---|
| ヘッダー | コンセプト文 | 「世界の空気を、衝動で測る。」13px・太字 |
| ヘッダー | バッジ | 「SIMULATION／仮の数値・模擬更新」等幅フォント 10px、細い枠線 |
| ステージ（中央） | エンブレム | 衝動ごとの大きな SVG イラスト（320×320 viewBox）。**このイラスト自体が投票ボタン** |
| ステージ | ラベル | 衝動名（例：一揆したい）。Dela Gothic One、30〜60px |
| ステージ | 集計数 | IBM Plex Mono 600、46〜120px、3桁カンマ区切り（例：123,456）。画面内で最大級の文字 |
| ステージ | 左右矢印 | 56px の円形アウトラインボタン。PC 幅のみ表示。端では無効化 |
| フッター | 残り投票枠 | 10本の縦長ピップ（塗り＝残り）＋短いメッセージ |
| フッター | ページインジケーター | 4本の横バー。現在位置のみ長く濃い。各バーはタップ可能 |

### 2.3 衝動ごとのビジュアル【モック】

| 順 | 衝動 | 背景色 | 文字色 | エンブレムのモチーフ |
|---|---|---|---|---|
| 1 | 一揆したい | `#C42A1C` | `#FFF4EA` | 傘連判状の筵旗を掲げ、竹槍を突き上げる群衆 |
| 2 | 革命したい | `#141212` | `#F4F0E8` | 逆さになって傾くピラミッドに赤い楔が突き刺さる |
| 3 | 国外脱出したい | `#18256B` | `#EEF0FA` | 国境の引かれた地球の殻を破り、光の軌跡が外へ飛び出す |
| 4 | 祭りたい | `#F0B21A` | `#1A120A` | 提灯と花火の下で、三つ巴の太鼓を打ち鳴らす |

- 衝動を切り替えると画面全体の背景色・文字色が 0.5 秒でトランジションする。
- 各エンブレムには常時ゆるやかに動く装飾アニメーション（旗が揺れる、提灯が揺れる等）がある。`prefers-reduced-motion: reduce` で停止する。

### 2.4 操作と挙動【モック】

| 操作 | 挙動 |
|---|---|
| 横スワイプ／ドラッグ | 8px 以上動いたらドラッグ開始。指に追従し、閾値 `min(80px, 幅×18%)` を超えたら隣へ切替。端では抵抗（移動量×0.3）がかかり、ループしない。縦スクロール（pan-y）は妨げない。PC でもマウスドラッグで同じ挙動 |
| 左右矢印ボタン | 前／次へ。先頭で「前」、末尾で「次」が無効 |
| キーボード ← → | 前／次へ |
| ページインジケーターのタップ | 該当の衝動へ直接移動 |
| エンブレムのタップ | 1票を投じる。スワイプ直後 350ms はタップを無視（誤投票防止） |
| 投票時の演出 | エンブレムが揺れる、集計数が拡大して戻る、「+1」が浮かんで消える、画面が一瞬フラッシュ |
| 上限時のタップ | 加算されず、残り枠表示が横に揺れる |

### 2.5 状態表示とメッセージ【モック】

| 状態 | エンブレム | ピップ | メッセージ |
|---|---|---|---|
| まだ一度も投票していない | 通常 | 10本塗り | 「絵を押して、1票」 |
| 投票済み・残りあり | 通常 | 残り本数だけ塗り | （なし） |
| 上限到達 | 半透明＋彩度低下、カーソル not-allowed、`aria-disabled="true"` | すべて空 | 「いまは、ここまで」 |

- ピップとメッセージは**現在表示中の衝動**の残り枠を示す（衝動ごとに独立）。

### 2.6 モックの模擬ロジック【モック】

- 初期値：一揆 123,456／革命 234,567／国外脱出 345,678／祭り 456,789
- 集計数 ＝「他ユーザー分（模擬値）」＋「自分の有効票数」
- 自分の票はタイムスタンプ付きで保持し、12時間を超えたものを除外（ローリングウィンドウ）。
- **1秒ごとに他ユーザー分の値をランダムに増減**させ、表示中の衝動の値が変わると集計数の左に小さな点が光る（ライブ表示）。
- 投票は楽観的更新：押した瞬間に +1 表示し、140ms 後に「模擬サーバー」が確定する。30% の確率で同じ票を二重送信し、ID で重複を弾く（冪等性の検証用）。
- 検証用プロパティ：集計ウィンドウを `12h`／`60s` で切替可能、ピップ表示の ON/OFF。
- 状態はメモリ上のみ。リロードすると投票履歴は消える。
- 未使用の定義：CSS `.vote` と表示値 `btn`（「＋1　衝動を投じる」／「いまは、ここまで」）が定義されているが、マークアップでは使われていない。

### 2.7 モックから読み取った設計方針

1. **1画面1衝動・数字が主役**。エンブレム → ラベル → 集計数の縦一列で、集計数が最も大きな文字。
2. **操作は「見る」と「押す」だけ**。説明文・グラフ・ランキングはない。
3. **イラストを押す＝衝動を投じる**。ボタンの文言で促すのではなく、絵そのものに触れさせる。
4. **衝動ごとに世界の色が変わる**。テーマ色で衝動を識別させ、ページインジケーターは控えめな横バー。
5. **手応えは演出で返す**。投票の結果は文章ではなくアニメーションで伝える。
6. **模擬であることを常に明示する**。ヘッダーの「SIMULATION」バッジ。
7. **上限は否定せず静かに伝える**。「いまは、ここまで」という柔らかい文言と、色を落とした状態。
8. **アクセシビリティ**：各ボタンに aria-label、`aria-live` で残り枠を通知、減速モーション設定を尊重、フォーカスリングを表示。

### 2.8 指示とモックの差異と解消結果

指示とモックが食い違う場合はモックを正とする（2026-10-23 決定）。すべて解消済み。

| ID | 指示 | モック | 解消結果（モック優先） |
|---|---|---|---|
| C-01 | 「投票ボタンを表示する」 | 専用の投票ボタンはなく、**エンブレム自体が投票ボタン**。専用ボタンの CSS と文言は定義済みだが未使用 | **エンブレムのタップで投票する。専用の投票ボタンは設けない**。未使用の定義（「＋1　衝動を投じる」）は実装しない（Q-01 解消） |
| C-02 | 他ユーザーのリアルタイム反映は「今回は実現しない」 | 他ユーザー分を1秒ごとにランダム増減させ、ライブ点滅で「動いている」ように見せる | **他ユーザー分の模擬変動とライブ点滅を実装する**（US-D3）。実データのリアルタイム反映は引き続き将来機能。模擬であることは「SIMULATION／仮の数値・模擬更新」バッジで常に明示する（Q-02 解消） |
| C-03 | 「控えめなページインジケーター」（操作は言及なし） | インジケーターはタップで直接移動できるボタン | **タップで直接移動できるインジケーターにする**。見た目は控えめな横バー（Q-03 解消） |

| C-05 | 残り枠の表示について言及なし | 10本のピップと「絵を押して、1票」「いまは、ここまで」 | **ピップと2つの文言をモックどおり実装する**（Q-05 解消） |
| C-06 | PC は「左右の矢印操作」 | 矢印ボタンに加え、キーボード←→、マウスドラッグ、インジケーターのタップでも切替可能 | **モックの切替手段をすべて実装する** |
| C-07 | 減速モーション設定について言及なし | `prefers-reduced-motion` で止めるのは常時の装飾アニメーションのみ。投票時の演出は止めない | **モックどおり常時アニメーションのみ停止する**（Q-10 解消） |

## 4. ユーザーストーリーと受け入れ条件

優先度：**P1** = MVP 必須（リリース1）／**P2** = MVP に含める（リリース2）／**フェーズ2** = AWS バックエンド導入後

### A. 開いて空気を知る

#### US-A1 1つの衝動を大きく表示する（P1）【確定】

ユーザーとして、アプリを開いたらすぐに1つの衝動を大きく見たい。なぜなら、ひと目でいまの空気を受け取りたいから。

- [ ] 初回表示で、衝動が1種類だけ画面に表示される（4種類の一覧表示はしない）。
- [ ] 表示中の衝動について、大きなアイコン（エンブレム）、ラベル、集計数が表示される。
- [ ] 初期表示の衝動は常に1番目の「一揆したい」である（前回の表示位置は記憶しない。URL でも指定しない）。
- [ ] 衝動の順序は「一揆したい → 革命したい → 国外脱出したい → 祭りたい」で固定されている。
- [ ] 幅 390px × 高さ 844px の表示領域で、エンブレム・ラベル・集計数・残り投票枠・ページインジケーターがスクロールせずに収まる。

#### US-A2 集計数を主役として表示する（P1）【確定】

ユーザーとして、衝動の数を何より先に読み取りたい。なぜなら、その数こそが世の中の空気の大きさだから。

- [ ] 集計数は画面上のテキストの中で最大の文字サイズで表示される。
- [ ] 集計数は3桁ごとのカンマ区切りで表示される（例：`123,456`）。
- [ ] 集計数は等幅数字で表示され、値が変わっても桁の位置がずれない。
- [ ] 集計方法の説明、時系列グラフ、ランキング、履歴、分析ダッシュボードは表示されない。

#### US-A3 模擬データであることを明示する（P1）【確定・表現はモック】

ユーザーとして、表示されている数が本物の集計ではないとわかるようにしたい。なぜなら、模擬の数を世の中の実態だと誤解したくないから。

- [ ] すべての衝動の表示中に、ヘッダー右側に「SIMULATION」「仮の数値・模擬更新」の2行のバッジが常に表示される。
- [ ] 実際の複数ユーザーの集計であると受け取れる文言（例：「全国の〇人が投票」「リアルタイム集計」）を表示しない。

#### US-A4 コンセプト文を表示する（P2）【モック】

ユーザーとして、このアプリが何を測っているのかを一言で知りたい。なぜなら、数の意味を説明なしで掴みたいから。

- [ ] ヘッダーに「世界の空気を、衝動で測る。」が表示される。
- [ ] コンセプト文は集計数より明らかに小さい文字で表示される。

### B. 他の衝動を見る

#### US-B1 モバイルで横スワイプして切り替える（P1）【確定】

モバイルユーザーとして、横にスワイプして別の衝動に切り替えたい。なぜなら、片手の自然な操作で他の空気も見たいから。

- [ ] 左へスワイプすると次の衝動、右へスワイプすると前の衝動が表示される。
- [ ] スワイプ中は表示が指に追従して動く。
- [ ] 移動量が閾値（モック：`min(80px, 表示幅×18%)`）未満で指を離すと、元の衝動に戻る。
- [ ] 先頭で右、末尾で左にスワイプしても切り替わらない（ループしない）。端では移動量に抵抗がかかる（モック：×0.3）。
- [ ] 切り替えでページ遷移・リロードが発生しない（URL もリロードもなし）。
- [ ] スワイプ操作の直後に、エンブレムへの誤タップで投票されない（モック：スワイプ終了後 350ms はタップ無視）。
- [ ] 縦方向のスクロール操作を妨げない。

#### US-B2 PC で左右の矢印ボタンで切り替える（P1）【確定】

PC ユーザーとして、左右の矢印ボタンで衝動を切り替えたい。なぜなら、マウスでは横スワイプしづらいから。

- [ ] 表示幅が広い場合（モック：700px 超）、ステージの左右に矢印ボタンが表示される。
- [ ] 右矢印で次の衝動、左矢印で前の衝動に切り替わる。
- [ ] 先頭では左矢印、末尾では右矢印が無効（押せない見た目）になる。
- [ ] 表示幅が狭い場合（モック：700px 以下）、矢印ボタンは表示されない。
- [ ] 矢印ボタンには「前の衝動」「次の衝動」に相当するアクセシブルな名前が付いている。

#### US-B3 ページインジケーターで位置を把握する（P1）【確定】

ユーザーとして、いま何番目の衝動を見ているかを控えめに知りたい。なぜなら、他にも衝動があることに気づきたいが、主役の数字の邪魔はされたくないから。

- [ ] 衝動の数（4つ）だけインジケーターが表示される。
- [ ] 現在表示中の衝動に対応するインジケーターだけが強調される（モック：長く、不透明）。
- [ ] 衝動を切り替えると強調位置が追従する。
- [ ] インジケーターは集計数・ラベルより視覚的に目立たない。

#### US-B4 衝動ごとにテーマ色が変わる（P2）【モック】

ユーザーとして、衝動ごとに画面の色が変わってほしい。なぜなら、ラベルを読まなくても今どの衝動を見ているか感じ取れるから。

- [ ] 各衝動の背景色・文字色が §2.3 の表のとおりになる。
- [ ] 切り替え時に背景色・文字色がなめらかに変化する（モック：0.5秒）。
- [ ] 各テーマで、ラベルと集計数の文字色と背景色のコントラスト比が 4.5:1 以上である。

#### US-B5 キーボードの左右キーで切り替える（P2）【モック】

PC ユーザーとして、キーボードの ← → キーでも切り替えたい。なぜなら、手早く全部の衝動を見比べたいから。

- [ ] メイン画面にフォーカスがある状態で → キーを押すと次、← キーで前の衝動に切り替わる。
- [ ] 先頭・末尾では、それ以上切り替わらない。
- [ ] 表示外の衝動のエンブレムには Tab キーでフォーカスが移らない。

#### US-B6 ページインジケーターから直接移動する（P2）【モック】

ユーザーとして、インジケーターを押して離れた衝動へ一気に移動したい。なぜなら、何度もスワイプしたくないから。

- [ ] インジケーターを押すと、対応する衝動へ直接切り替わる。
- [ ] 各インジケーターに衝動名のアクセシブルな名前が付いている。
- [ ] タップ領域は見た目のバーより大きい（モック：34×40px）。

### C. 衝動を投じる

#### US-C1 エンブレムを押して1票を投じる（P1）【確定・操作形態はモック】

ユーザーとして、表示中の衝動に1票を投じたい。なぜなら、自分が世の中に抱いた衝動を数に加えたいから。

- [ ] 表示中の衝動のエンブレム（大きなイラスト）を1回押すと、表示中の衝動の集計数が 1 増える。
- [ ] 専用の投票ボタンは表示しない。
- [ ] 他の3つの衝動の集計数は変わらない。
- [ ] エンブレムはボタンとして実装され、キーボード（Enter／Space）でも投票できる。
- [ ] エンブレムには「〇〇（n票）に1票を投じる」というアクセシブルな名前が付いている（n は3桁カンマ区切りの現在値）。
- [ ] 投票でページ遷移・リロードが発生しない。

#### US-C2 投票の手応えを感じる（P2）【モック】

ユーザーとして、押した瞬間に手応えを感じたい。なぜなら、自分の衝動が確かに届いたと実感したいから。

- [ ] 投票すると、エンブレムが揺れる、集計数が一瞬拡大する、「+1」が浮かんで消える、画面が一瞬フラッシュする、の演出が起きる。
- [ ] `prefers-reduced-motion: reduce` の環境でも、これらの演出は再生される（モックどおり）。
- [ ] 連続で投票しても、演出が毎回再生される。
- [ ] 上限到達時の操作では、この演出は起きない。

#### US-C3 初回の操作ガイドを見る（P2）【モック】

初めて使うユーザーとして、何を押せば投票できるのかを知りたい。なぜなら、ボタンらしいボタンがなくても迷わず投票したいから。

- [ ] 一度も投票していない間、残り投票枠の横に「絵を押して、1票」が表示される。
- [ ] どの衝動でも1回投票すると、このガイドはどの衝動でも表示されなくなる。
- [ ] 上限到達時は、ガイドの代わりに上限のメッセージが表示される。

### D. 反映を確かめる

#### US-D1 集計数が即座に増える（P1）【確定】

ユーザーとして、投票した直後に数が増えるのを見たい。なぜなら、自分の1票が世の中の数に加わったことを確かめたいから。

- [ ] エンブレムを押した瞬間に、通信待ちやローディング表示なしで集計数が +1 された値に変わる（楽観的更新）。
- [ ] データ層での確定後（モックの模擬サーバー：約140ms 後）も、表示された値が巻き戻らない。
- [ ] 確定待ちの間に重ねて押しても、二重に加算されない。
- [ ] 別の衝動に切り替えて戻っても、増えた値が維持されている。
- [ ] 集計数は「有効投票数」を表し、同じユーザーの複数票はそれぞれ 1 として数えられる（ユニークユーザー数ではない）。

#### US-D2 残り投票枠を確かめる（P2）【モック】

ユーザーとして、この衝動にあと何票投じられるかを知りたい。なぜなら、上限に達する前に自分の残りを把握したいから。

- [ ] 表示中の衝動について、残り投票枠が10本のピップで表示される（塗りつぶし＝残り、枠線のみ＝使用済み）。
- [ ] 投票するたびに残り枠の表示が 1 減る。
- [ ] 衝動を切り替えると、その衝動の残り枠が表示される（4種類は独立）。
- [ ] 残り枠の変化はスクリーンリーダーに通知される（`aria-live="polite"`）。

#### US-D3 他ユーザー分の模擬変動を見る（P2）【モック】

ユーザーとして、自分が投票しなくても数が動いているのを見たい。なぜなら、世の中の空気が刻々と変わっていると感じたいから。

- [ ] 約1秒ごとに、4種類それぞれの「他ユーザー分」の値が増減する。
- [ ] 変動はモックのアルゴリズムに従う：1秒あたりの基準量 `rate = 他ユーザー分 ÷ 43,200`（12時間の秒数）に対し、流入 `round(rate × 乱数[0.3, 1.7))` を加え、失効 `round(rate × 乱数[0.3, 1.7))` を引く。
- [ ] 他ユーザー分は 0 未満にならない。
- [ ] 表示中の衝動の値が変化したとき、集計数の左にある小さな点が一瞬光る（モック：0.9秒で元の薄さに戻る）。
- [ ] 自分の票は模擬変動とは独立に加算され、模擬変動で自分の票が消えることはない。
- [ ] 乱数と時計を差し替えて、変動を自動テストで検証できる。
- [ ] 模擬変動中も「SIMULATION／仮の数値・模擬更新」バッジが表示されている（US-A3）。

### E. 上限に達する

#### US-E1 衝動ごとに12時間で10票まで投じられる（P1）【確定】

ユーザーとして、1つの衝動に投じられる票数に上限があってほしい。なぜなら、一人の連打で世の中の空気が歪まないようにしたいから。

- [ ] 1つの衝動について、直近12時間以内の自分の票が 10 票ある状態では、投票操作をしても集計数が増えない。
- [ ] 上限は衝動ごとに独立している（「一揆したい」が 10 票でも「革命したい」には投票できる）。
- [ ] 10 票目は受け付けられ、11 票目は受け付けられない。
- [ ] 判定は「最後に投票してから12時間」ではなく、各票の投票時刻から12時間のローリングウィンドウで行う。

#### US-E2 上限に達したことがわかる（P1）【確定・表現はモック】

ユーザーとして、もう投票できない状態だとひと目でわかりたい。なぜなら、押しても反応しない理由を知りたいから。

- [ ] 表示中の衝動が上限に達すると、投票操作の要素が無効状態の見た目になる（モック：半透明＋彩度低下）。
- [ ] 残り投票枠の横に「いまは、ここまで」が表示され、ピップがすべて空になる。
- [ ] 投票操作の要素に、投票できない状態であることがアクセシブルに伝わる（モック：`aria-disabled="true"`）。
- [ ] 上限に達していない別の衝動に切り替えると、通常の状態で表示される。

#### US-E3 12時間経過で投票枠が回復する（P1）【確定】

ユーザーとして、時間が経てばまた投票できるようになってほしい。なぜなら、空気が変われば新しい衝動が湧くから。

- [ ] 投票から12時間を経過した票は、自分の投票枠のカウントから除外され、その分だけ再び投票できる。
- [ ] 投票から12時間を経過した自分の票は、集計数からも除外される（集計数がその分減る）。
- [ ] アプリを開いたままでも、時間経過で表示（集計数・残り枠・上限状態）が更新される。
- [ ] 時刻を差し替えられる仕組み（テスト用の時計）で、12時間経過を自動テストで検証できる。

#### US-E4 上限中に押したときに反応がある（P2）【モック】

ユーザーとして、上限中に押してしまったときも何らかの反応がほしい。なぜなら、アプリが固まったと誤解したくないから。

- [ ] 上限中に投票操作をすると、残り枠の表示が横に揺れる。
- [ ] このとき集計数は変化せず、投票の演出も起きない。

#### US-E5 リロード後も投票履歴が保持される（フェーズ2）

ユーザーとして、ページを開き直しても自分の投票枠が正しく残っていてほしい。なぜなら、開き直すたびに上限が戻るのは不自然だから。

- フェーズ1はモックどおり投票履歴をメモリだけに持つ。リロードすると自分の票・残り枠・模擬変動はすべて初期状態に戻る（Q-06 解消）。
- フェーズ2で、サーバー側に投票履歴を保存して実現する（F-03）。

#### US-E6 投票枠の回復時刻を知る（実装しない）【モック】

ユーザーとして、いつまた投票できるのかを知りたい。なぜなら、上限に達したとき次の機会を待ちたいから。

- モックに回復時刻・残り時間の表示はないため、実装しない（Q-07 解消）。

### V. 検証用の機能（開発者向け）

モックにある検証用の機能を残す（2026-10-24 決定、Q-11 解消）。利用者向けの画面には出さない。

切り替えは**ビルド時の環境変数**で行う（2026-10-24 決定、Q-14 解消）。公開用ビルドでは環境変数を設定せず、常に既定値で動かす。URL のパラメーターや画面上の操作では切り替えられない。

| 環境変数 | 値 | 既定値 | 対応ストーリー |
|---|---|---|---|
| `NUXT_PUBLIC_VOTE_WINDOW` | `12h`／`60s` | `12h` | US-V1 |
| `NUXT_PUBLIC_SHOW_PIPS` | `true`／`false` | `true` | US-V2 |

※ 二重送信の模擬（US-V3）はモックどおり常に有効で、切り替えの対象にしない。

#### US-V1 集計ウィンドウを短縮して確認する（P2）【モック】

開発者として、12時間のローリングウィンドウを60秒に短縮したい。なぜなら、上限到達と枠回復の挙動を実機で短時間に確かめたいから。

- [ ] ビルド時に `NUXT_PUBLIC_VOTE_WINDOW=60s` を指定すると、集計ウィンドウが60秒になる。指定しないとき、または `12h`／`60s` 以外の値のときは `12h` になる。
- [ ] `60s` のとき、投票から60秒で自分の票が集計から外れ、投票枠が回復する。
- [ ] 公開用ビルドでは `12h` で動き、URL のパラメーターや画面上の操作では変更できない。

#### US-V2 残り投票枠の表示を切り替える（P2）【モック】

開発者として、ピップ（残り投票枠）の表示・非表示を切り替えたい。なぜなら、ピップがない場合の画面の見え方を比較したいから。

- [ ] ビルド時に `NUXT_PUBLIC_SHOW_PIPS=false` を指定すると、ピップが表示されない。指定しないとき、または `true`／`false` 以外の値のときは表示される。
- [ ] OFF のときもメッセージ（「絵を押して、1票」「いまは、ここまで」）は表示される。

#### US-V3 二重送信を模擬する（P2）【モック】

開発者として、投票の二重送信が起きても1票しか数えられないことを確かめたい。なぜなら、フェーズ2で通信が再送されても票が重複しないようにしたいから。

- [ ] モックの模擬サーバーは、投票の確定時に 30% の確率で同じ票 ID をもう一度送る（モックどおり）。
- [ ] 同じ票 ID は1票としてしか記録されず、集計数も残り枠も二重に変化しない。
- [ ] 確率は乱数の注入で 0%／100% に固定してテストできる。
